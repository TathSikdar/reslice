# ADR-006 — The 3D view is a mode of the fourth pane, not a layout

## Context

FR-610 as written says "the 3D view shall be selectable as a layout", and the Phase 2 spec
flags that this needs a control that does not exist: a layout selector, offering something
like *2×2 MPR*, *MPR + 3D* and *3D only*. That is how commercial workstations do it, and it
is the obvious answer.

Phase 1 §1.6 is the constraint on the other side. Every visible control has to be
explainable to the bottom in a ten-minute demo, and a control that exists because other
products have one is exactly what that rule is for. The viewer currently has eight visible
controls; a layout selector would be a ninth, and it would be the only one whose whole
purpose is to rearrange other controls rather than to change what is on screen.

## Decision

The 3D view is one of the entries in the dropdown that already chooses what the fourth pane
shows. It reads *MIP · MinIP · Average · 3D*.

No layout selector, no full-window 3D mode, no second arrangement of panes. FR-203's
double-click maximize already covers "I want to see this one bigger", and it covers it for
all four panes with a gesture rather than a control.

## Consequences

**The dropdown is coherent, not a dumping ground.** MIP, MinIP, Average and a volume
rendering all answer the same shape of question — what is along this direction, rather than
what is at this plane. Three of them answer it by reducing a slab to one number per ray and
the fourth answers it by compositing colour along the ray. Putting them in one control says
that, and someone asking "why is 3D under Slab?" gets a real answer rather than an apology.

**Phase 2 adds no layout chrome.** Two controls arrive with the 3D view — a preset dropdown
and a shading checkbox — and both are only visible while it is up, because a shading
checkbox next to a MIP is a control that does nothing, which is worse than one that is
missing.

**The export needed a small change.** FR-409's fourth target now names a cell rather than a
control, and two controls share that cell. It captures whichever is actually on screen;
capturing the hidden one would have written out a stale bitmap, which is the one failure an
export must not have. The entry is named "Slab / 3D" so the dropdown says what the cell is.

**No side-by-side MPR and 3D at full height.** This is the real cost. On a wide monitor a
half-and-half layout is a better use of the space than a 2×2 with one cell being 3D, and
this decision gives that up. It is recoverable: the layout selector would be additive and
would not change any of the four panes, so if the demo turns out to want it, it is a
control to add rather than a design to undo.

**FR-610 is satisfied differently from how it is written.** The requirement says "as a
layout"; this delivers "as a selectable mode of a pane", which meets the intent — the 3D
view is selectable and exportable — and not the letter. Recorded here rather than quietly,
and the spec has been amended to match rather than left disagreeing with the code.
