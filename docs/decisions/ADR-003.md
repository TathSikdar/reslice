# ADR-003 — Series rejection is an exception carrying a typed reason

## Context

FR-105, FR-106 and FR-107 all end the same way: the series cannot be reconstructed and
the user must be told why, calmly, in words (§1.6 rule 3 — failure modes must be visible
and narratable, not a stack trace).

Two shapes were considered. A result type, `ValidationResult(bool Ok, Reason?, string?)`,
which the caller inspects. Or an exception carrying the same fields.

A result type is the more fashionable answer and the usual advice: exceptions are for the
exceptional, and a malformed series is expected input. But the honest question is what
the caller does with it, and here every caller does the same thing — abandon the load and
show the message. There is no partial success to salvage and no branch where validation
failed but work continues. A result type would be checked immediately and unwrapped in
one place, which is an exception with extra ceremony and a silent path if someone forgets
to check.

## Decision

`SeriesRejectedException`, carrying a `SeriesRejectionReason` enum alongside the
human-readable message.

The enum exists so the UI can branch on the class of failure without parsing prose, and
so tests assert on the reason rather than on wording that will be reworded. The message
exists because an enum name is not something to put in front of a user.

## Consequences

- The rejection path cannot be forgotten. An unchecked result type fails open; an
  uncaught exception fails loud.
- The probe catches it explicitly and prints `Rejected ({Reason}): {Message}`, which
  keeps the enum and the prose visibly connected and is the demo beat in §14.2.
- Every rejection test asserts on the reason, and separately on a distinctive fragment of
  the message where the message is the point (a missing slice and merely uneven spacing
  share a reason but must not share a diagnosis).
- If a future caller ever needs to try several series and keep the first that loads, this
  becomes a try/catch in a loop rather than a natural fold. That is acceptable, and is
  the one scenario that would justify revisiting this.
